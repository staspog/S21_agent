# Личный контекст ассистента: контракт MVP

Статус на 2026-11-19: API и агент с MCP выпущены в production; контроллер подтвердил здоровье и точные релизы `r-66bacfb5d20c0dd7cb1ce1f4` и `r-bcf3cbdd803f9b3442dd2d78`. Внешние запросы без токена получили 401. Проверка с сохранённой учётной записью canary подтвердила оба инструмента и ответы агента для пустого календаря и имеющегося проекта; проверка с созданием слота не выполнялась. Ежедневная personal-canary не включена. Бизнес-требования и случаи приёмки находятся в Obsidian в разделе School 21/агент/Бизнес-требования.

Целевая архитектура: MCP-сервер работает в процессе s21_server_api на защищённом Streamable HTTP endpoint; агент выступает MCP-клиентом. API предоставляет только get_my_calendar и get_my_projects, повторно используя логику платформы. Перенос MCP из процесса агента требует совместной проверки API, агента и сетевого доступа до выпуска. Существующие HTTP endpoints остаются совместимыми.

- `/ask` принимает только действительную платформенную авторизацию, проверенную серверным API с запросом к платформе. Отсутствующий или отклонённый токен даёт 401; недоступность проверки не считается отказом авторизации и не раскрывает данные.
- История и память ограничены подтверждённым пользователем и идентификатором диалога. Токены не попадают в состояние графа, вызовы модели и логи. MCP-инструменты доступа к календарю и проектам выполняются только от имени проверенного пользователя и только на чтение.
- Календарь различает собственные свободные слоты, проверки, защиты, мероприятия и заявки. Пустой результат, ошибка источника и отказ доступа не взаимозаменяемы. По умолчанию используется Europe/Moscow, клиент может передать допустимый часовой пояс.
- Вопросы о личном календаре и проектах используют свежие данные MCP, общие вопросы сохраняют RAG и поиск Rocket.Chat. Инструкции в данных источника не имеют полномочий.
- Для приёмки ежедневная canary до начала своего тестового слота запрашивает «Что у меня сегодня?» и сверяет ответ с подтверждённым календарём: свободный слот, локальное время и корректная роль. Не требуется буквальное совпадение ответа; отрицание наличия слота не является успехом. Отсутствие в календаре после начала может быть следствием автоматического истечения, поэтому не доказывает удаление или отсутствие записи.
- При истечении предусмотренного времени ожидания canary прекращает ждать ответ и переходит к безопасной очистке в пределах окна, описанного в `../../s21_canary/docs/personal-mcp-canary-spec.md`. Сбой модели или MCP не отменяет обязанность безопасной очистки.
- Перед выпуском обязательны тесты из Obsidian, проверка изоляции аккаунтов, отсутствия утечек, совместимости существующего клиента, отказов и отката. Production-развёртывание отдельно авторизуется пользователем.
# Граница исходящих запросов

Идентификация пользователя и чтение его данных платформы выполняются только через настроенный S21 Server API. `S21_SERVER_API_BASE` не должен указывать непосредственно на `platform.21-school.ru` или `auth.21-school.ru`: такая конфигурация отклоняется до отправки токена. Rocket.Chat и GigaChat являются отдельными внешними сервисами и используют собственные соединения. Кодовая проверка доменов не заменяет сетевой политики egress и не доказывает фактическую конфигурацию production.
