# Логирование в проекте

## Обзор

В проекте реализовано подробное пошаговое логирование всех операций с использованием стандартного модуля `logging` Python.

## Структура логирования

### Уровни логирования

- **INFO** - Основные события (запросы, ответы, важные действия)
- **DEBUG** - Детальная информация для отладки
- **WARNING** - Предупреждения (некритичные проблемы)
- **ERROR** - Ошибки (с полным traceback)

### Формат логов

**Консоль:**
```
2025-01-21 12:34:56 | INFO     | s21_agent.agents | [Session: session_123] Классификация запроса: первый проект по си
```

**Файлы:**
```
2025-01-21 12:34:56 | INFO     | s21_agent.agents | [agent.py:75] | [Session: session_123] Классификация запроса: первый проект по си
```

## Файлы логов

Логи сохраняются в директории `logs/`:

- `app_YYYYMMDD.log` - Все логи за день
- `errors_YYYYMMDD.log` - Только ошибки за день

## Что логируется

### API (`src/api_agent.py`)

- Входящие запросы с IP адресом
- Session ID для каждого запроса
- Время обработки запросов
- Ошибки с полным traceback
- Управление сессиями (создание, удаление)

**Пример:**
```
[API] ===== Новый запрос /agent/ask =====
[API] IP: 192.168.1.1
[API] Запрос: первый проект по си
[API] Session ID: session_1234567890
[API] ===== Запрос обработан успешно =====
[API] Processing time: 2.345s
```

### Агент (`src/agents/agent.py`)

- Классификация запросов
- Планирование поиска проектов
- Уточняющие вопросы (номер, тип, текст)
- Фильтрация проектов
- Формирование ответов
- Маршрутизация по графу
- Время выполнения каждого этапа

**Пример:**
```
[Session: session_123] ===== Начало обработки запроса =====
[Session: session_123] Классификация запроса: первый проект по си
[Session: session_123] Классификация завершена: ТЕХНИЧЕСКИЙ (время: 0.234s)
[Session: session_123] Планирование поиска проекта (вопросов задано: 0)
[Session: session_123] Будет задан вопрос: Уточните, пожалуйста, о каком проекте идет речь?
[Session: session_123] ===== Запрос обработан =====
```

### LLM клиент (`src/llm/client.py`)

- Вызовы GigaChat API
- Длина промптов и ответов
- Время выполнения запросов
- Ошибки API

**Пример:**
```
[LLM] Вызов GigaChat API
[LLM] Промпт (первые 200 символов): Ты помощник для поиска проектов...
[LLM] Ответ получен (время: 1.234s, длина: 456 символов)
```

### База данных (`src/database/mock_db.py`)

- Поиск проектов
- Получение заданий
- Предупреждения о несуществующих проектах

**Пример:**
```
[DB] Поиск проекта: SimpleBashUtils
[DB] Проект найден: SimpleBashUtils
[DB] Получение заданий для проекта: SimpleBashUtils
[DB] Задания получены для SimpleBashUtils (длина: 1234 символов)
```

## Session ID

Каждый запрос получает уникальный `session_id`, который используется во всех логах для отслеживания полного пути запроса через систему.

Формат: `session_<timestamp>` или пользовательский ID сессии.

## Поиск в логах

### Найти все логи для конкретной сессии:
```bash
grep "Session: session_123" logs/app_20250121.log
```

### Найти все ошибки:
```bash
grep "ERROR" logs/errors_20250121.log
```

### Найти все запросы к API:
```bash
grep "\[API\]" logs/app_20250121.log
```

### Найти все вызовы LLM:
```bash
grep "\[LLM\]" logs/app_20250121.log
```

### Найти все операции с БД:
```bash
grep "\[DB\]" logs/app_20250121.log
```

## Настройка уровня логирования

Уровень логирования можно изменить в `src/utils/logger.py`:

```python
# Для разработки - показывать все
root_logger = setup_logger("s21_agent", logging.DEBUG)

# Для продакшена - только важное
root_logger = setup_logger("s21_agent", logging.INFO)
```

## Ротация логов

Логи автоматически создаются по дням. Старые логи можно удалять вручную или настроить автоматическую ротацию через cron:

```bash
# Удалить логи старше 30 дней
find logs/ -name "*.log" -mtime +30 -delete
```

## Мониторинг

Рекомендуется использовать инструменты для мониторинга логов:

- **ELK Stack** (Elasticsearch, Logstash, Kibana)
- **Grafana Loki**
- **Sentry** для ошибок
- **CloudWatch** (если на AWS)

## Примеры использования

### Отслеживание полного пути запроса:

1. Найти session_id в логах API
2. Найти все логи с этим session_id
3. Проследить весь путь через систему

```bash
# 1. Найти session_id
grep "Новый запрос" logs/app_20250121.log | tail -1

# 2. Извлечь session_id и найти все логи
SESSION_ID="session_1234567890"
grep "$SESSION_ID" logs/app_20250121.log
```

### Анализ производительности:

```bash
# Найти все запросы с временем обработки > 5 секунд
grep "Processing time" logs/app_20250121.log | awk -F' ' '$NF > 5'
```

### Поиск проблем:

```bash
# Найти все ошибки с traceback
grep -A 10 "ERROR" logs/errors_20250121.log
```
